# Context Interpretation 테스트 시나리오

이 문서는 전통적 키워드 방식과 Agentic 방식의 차이를 검증하기 위한 테스트 케이스이다.

---

## 시나리오 1: 부정 문맥 (Negation)

**이슈:**
```
제목: 이것은 bug가 아닌 것 같은데 질문이 있습니다
본문: 로그인 페이지에서 비밀번호가 8자 이상이어야 하나요?
      이게 정상 동작인지 알고 싶습니다.
```

| 방식 | 결과 | 정확도 |
|------|------|--------|
| 키워드 | `bug` (❌ "bug" 포함) | 오분류 |
| Agentic | `question`, `area:auth`, `priority:low` (✅) | 정확 |

**에이전트의 추론:**
> "bug가 아닌 것 같은데"는 부정 표현이다. 본문은 "알고 싶습니다"로 끝나는 질문이다.
> 비밀번호 규칙에 대한 질문이므로 auth 영역이고 우선순위는 낮다.

---

## 시나리오 2: 키워드와 의미 불일치 (Semantic Mismatch)

**이슈:**
```
제목: feature flag 시스템 장애
본문: 프로덕션 환경에서 feature toggle을 활성화했더니
      전체 사용자에게 500 에러가 발생합니다.
      롤백이 필요한 상황입니다.
```

| 방식 | 결과 | 정확도 |
|------|------|--------|
| 키워드 | `enhancement` + `bug` (❌ 충돌) | 오분류 |
| Agentic | `bug`, `area:feature-flags`, `priority:critical` (✅) | 정확 |

**에이전트의 추론:**
> "feature"가 포함되어 있지만 "장애", "500 에러", "롤백 필요"라는 맥락에서
> 이것은 기능 요청이 아닌 심각한 버그이다.
> 프로덕션 전체 사용자 영향이므로 critical 우선순위다.

---

## 시나리오 3: 암시적 버그 (Implicit Bug Report)

**이슈:**
```
제목: 저장 버튼을 누르면 아무 반응이 없어요
본문: 프로필 편집 페이지에서 정보를 수정한 후
      저장 버튼을 클릭해도 아무 일도 일어나지 않습니다.
      새로고침하면 수정 내용이 사라집니다.
```

| 방식 | 결과 | 정확도 |
|------|------|--------|
| 키워드 | 라벨 없음 (❌ "bug" 키워드 없음) | 누락 |
| Agentic | `bug`, `area:ui`, `priority:high` (✅) | 정확 |

**에이전트의 추론:**
> "아무 반응이 없어요", "아무 일도 일어나지 않습니다"는 기능 오작동을 의미한다.
> 데이터가 저장되지 않는 것은 사용자 경험에 큰 영향을 주므로 high 우선순위.
> UI 인터랙션 문제이므로 area:ui.

---

## 시나리오 4: 복합 의도 (Mixed Intent)

**이슈:**
```
제목: API 타임아웃 문제 + 개선 제안
본문: 현재 /api/reports 엔드포인트가 대용량 데이터에서 30초 타임아웃이 됩니다.
      이것이 알려진 이슈인지 확인 부탁드립니다.
      가능하다면 페이지네이션 기능을 추가해주시면 좋겠습니다.
```

| 방식 | 결과 | 정확도 |
|------|------|--------|
| 키워드 | `enhancement` (⚠️ 부분 정확) | 불완전 |
| Agentic | `bug` + `enhancement`, `area:api`, `priority:medium` (✅) | 정확 |

**에이전트의 추론:**
> 이 이슈는 두 가지 의도를 담고 있다:
> 1. 타임아웃 문제는 현재 동작의 결함 → bug
> 2. 페이지네이션 추가는 개선 제안 → enhancement
> 두 라벨 모두 적절하다. API 관련이고, 서비스가 완전히 중단되지는 않으므로 medium.

---

## 시나리오 5: 문화적/언어적 맥락 (Linguistic Context)

**이슈:**
```
제목: 대시보드가 좀 이상해요
본문: 어제까지 잘 되던 대시보드 차트가 오늘 갑자기 데이터를 안 보여줍니다.
      다른 팀원도 같은 증상이래요.
```

| 방식 | 결과 | 정확도 |
|------|------|--------|
| 키워드 | 라벨 없음 (❌ 어떤 키워드에도 매칭 안됨) | 누락 |
| Agentic | `bug`, `area:ui`, `priority:high` (✅) | 정확 |

**에이전트의 추론:**
> "이상해요"는 비공식적 표현이지만 문제 보고의 맥락이다.
> "잘 되던 것이 안 된다" = 기존 기능의 regression.
> 다수 사용자 영향이므로 high 우선순위.

---

## 정리: Context Interpretation이 해결하는 것

```
전통적 자동화:  텍스트 → 키워드 추출 → 규칙 매칭 → 라벨
                (표면적, 기계적, 맥락 무시)

Agentic 방식:   텍스트 → 의미 파악 → 의도 추론 → 판단 → 라벨
                (맥락 이해, 부정 인식, 암시적 의미 파악)
```

에이전트는 다음을 이해할 수 있다:
1. **부정 표현**: "bug가 아닙니다" → bug 아님
2. **의미적 연결**: "멈춤", "에러", "안 됨" → 모두 bug를 의미할 수 있음
3. **복합 의도**: 하나의 이슈에 여러 유형이 섞여 있을 때
4. **영향도 추론**: "프로덕션", "전체 사용자" → 높은 우선순위
5. **비공식 표현**: "이상해요", "좀 그래요" → 문제 보고로 인식
